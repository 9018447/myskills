# 仓库全景简报（repo-briefing）

为新接手的决策者产出一份 markdown 简报，让对方不读源码也能快速掌握：这个仓库是什么、目录怎么分、架构怎么串起来、历史上发生了什么、关键决策为什么这么做、现在做到哪、下一步做什么。全程只读，不改代码、不写进仓库。

## 触发

用户说"给我一份仓库简报 / onboarding / 新接手的决策者要了解这个项目 / 介绍一下仓库内容和开发历史"时执行本流程。

## 流程（三步）

### 第一步：探索 —— 摸清仓库长什么样

先以代码图为主引擎起手，再查缺补漏，**只读**：

```
gitnexus-exploring skill        # 主引擎：绑定 repo、query 核心概念 →
                                    context / trace 摸模块归属、调用链、执行流
zvec_grep_search（语义）         # 查缺补漏：gitnexus 覆盖不到的语义概念、跨文件综合
```

- **`gitnexus-exploring` 打头**：调用该 skill 走它的 CLI 流程（`node .gitnexus/run.cjs status --repo .` 先确认索引 fresh，过期就 `analyze --index-only` 重索引——索引缺失时 `query` 返回空会误导，不能用空结果当"没人用"）。
- **`zvec_grep_search` 兜底**：gitnexus 只覆盖 main 分支、只索引被模块 include 的入口，遗留目录/工作区分支在它看不到；这些语义盲区用 `zvec_grep_search` 补齐。
- 关键文件（入口模块、核心组件、README/根文档）用 `Read` 精读。
- **不用 `rg` / `zg --rg`**：精确匹配路径由 `Read` 直接读目标文件覆盖，不引入文本检索兜底（避免降级到 rg）。

这一步的产物：仓库定位、技术栈、目录职责清单、核心概念清单。

### 第二步：脉络梳理 —— 它为什么这么设计

- **`/how`**（pstack:how）：架构怎么拼、运行时数据怎么流、模块归属在哪层。回答"**现在**怎么运转"。
- **`/pstack:why`**：关键设计决策的动机、取舍、repo 级规约、历史回归教训。回答"**当初**为什么这样选"。

两者同时消耗，别只做其一：`how` 给结构，`why` 给动机，简报要两块都有。产物：关键决策清单（决策 + 一句话理由 + 证据来源）。

### 第三步：成稿 —— 套模板产出简报

套用下方模板写一份 markdown 简报。**以对"刚接手、不了解代码的决策者"讲话的口吻**：不用内部黑话，术语出现时随手带一句它在这里的实际作用；只写有出处的事实（源码、git 历史、ADR、handoff、README），拿不准就注明"未核实"而不是编。

产物：一份 markdown 文件。放到用户指定的路径；没指定就放 `./REPO_BRIEFING.md`。完成后只向用户汇报文件路径 + 一句话摘要 + 简报里的关键结论，不要把整份简报贴回聊天。

## 简报模板

下面每个小节都该有，空数据的小节写"暂缺"并注明可能去哪查，不要留着空白标题。

### 一段话定位
三到五句讲清仓库是什么、为谁服务、解决什么问题。非技术读者也能懂。

### 技术栈与目录结构
- 语言/框架/运行时、主要依赖。
- 目录骨架 → 各自职责（用 file tree 展示）。
- 哪些目录是**遗留/不再生效**（有就标明，接手的决策者最怕在死代码上浪费理解）。

### 架构脉络：现在怎么运转
- 核心概念与模块（第一步探索的产物）。
- 跑一次主流程会经过哪些环节（伪代码或 call tree）。
- 模块间怎么交互（组件图 / Mermaid）。

### 开发历史
- 时间轴：项目从哪来、经历了哪些阶段（用 git 历史倒序梳理，标记里程碑）。
- 关键转折点：架构推翻、方向更换、大重构。
- 历史教训：踩过的坑、（postmortem 里）沉淀下来的约定。

### 关键决策与理由
- 每条：**做了什么决策 → 为什么这么做 → 权衡了什么**（来自 `/pstack:why` 和 ADR）。
- 若仓库有 `docs/adr/`，逐条列 ADR 编号 + 一句话主题。

### 工程约定
一次性讲清 how to work here：测试怎么跑、群组怎么分、格式/静态检查、CI 做什么、代码风格和命名、是否有编码分工规则。

### 当前状态与下一步
- 当前分支/最近提交在做什么。
- **尚未完成的诉求 / 开放目标 / 遗留 todo**（若 handoff 或 spec 里有，单列）。
- Roadmap：已知下一步计划。
- 给决策者的建议：最该先读的文件、最该先关注的模块、潜在风险点。
