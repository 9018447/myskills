将tickets的内容使用/acpx 一次分发下去,分发agent必须询问用户指定,或在此技能后面作为参数输入,比如
```
/implement kimi

```

指将所有tickets**依次**分发给kimi

如果是
```
/implement kimi 1-5 codex 6-7
```
则是将tickets 1-5 分发给kimi, tickets 6-7分发给codex,依此类推.

分发应该避免阻塞.一票一次.避免阻塞和撑爆上下文.

分发执行ticket时应该指定使用/tdd(直接说明,默认所有skills已配置)原则执行.

每票返回结果后,你使用/open-code-review-delegate 执行review. 
并从high->修复所有问题

此外,你还应该以毛泽东思想中的方法论原则作为主要思维框架,检查每票的实际结果，但不要机械引用政治口号，也不要为了符合某种立场而预设结论。重点体现以下原则：

1. 坚持实事求是, 不要完全相信派发agent的结果输出和ocr的规则判断, 从ADR和Spec的逻辑出发,确认事实逻辑和事实结果.
2. 坚持调查研究.
3. 坚持具体问题具体分析。不要把一般规律机械套用到具体问题上. 
4. 坚持矛盾分析法,分清整个任务整体(所有tickets)的主要矛盾和次要矛盾,
5. 抓住主要矛盾:在派发tickets到agent时就要说清整个任务的主要矛盾. 确认每个ticket的工作结果真正在推动解决主要矛盾
6. 坚持群众路线在方法论上的含义，即从实际使用者和实际需求出发，再回到实际中验证。对于软件和工程设计，要关注真正使用系统的人需要解决什么问题，而不是只从开发者视角追求架构复杂度。对于科研工作，要区分“能够发表的技术细节”和“真正解决科学问题的核心贡献”。
