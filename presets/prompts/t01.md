## 技能定位

deep-research：**编排者给计划的网络深入研究工作流**。编排者（主 agent）在运行前写好任务契约（研究主题 + 子方向计划），工作流按「计划→广域搜索→逐子方向深潜→综合闭环」执行；搜索一律由可信脚本确定性调用 metaso HTTP API，AI（codex）只负责提查询、读结果、写产出，不接触网络。最终 report 必须通过机制化「逻辑闭环」验收：每个子方向有 findings 与报告章节、每条引用 [S#] 可解析到来源登记表、搜索预算守恒、写入不越界。

## 任务契约（编排者运行前写 `.agent/luna/task.json`，路径与 explore-repo 同约定）

```json
{
  "task_id": "research-<slug>-001",
  "topic": "研究主题（一句话）",
  "objective": "研究要回答的核心问题",
  "plan_file": null,
  "directions": [
    {"id": "D1", "title": "子方向标题", "questions": ["要回答的问题"]}
  ],
  "scopes": ["webpage"],
  "broad_queries": 4,
  "queries_per_direction": 3,
  "size_per_query": 10,
  "max_searches": 24,
  "max_fetches": 8,
  "fulltext_max_chars": 40000,
  "allowed_write_paths": [],
  "constraints": [],
  "max_attempts": 2,
  "step_timeout_seconds": 1200,
  "timeout_seconds": 5400
}
```

契约校验（preflight，fail=exit 2，风格照抄 explore-repo 的 contract()）：
- 必填 `task_id`（`[A-Za-z0-9][A-Za-z0-9._-]*`）、`topic`、`objective`、`directions`。
- `directions` 1..12 个；id 唯一且 `^[A-Za-z0-9][A-Za-z0-9_-]{0,15}$`；每个 1..8 条非空 questions。
- `scopes` 子集于 {webpage, news, wechat, arxiv, github}，默认 ["webpage"]。
- 数值域：broad_queries 1..6 默认 4；queries_per_direction 1..6 默认 3；size_per_query 1..10 默认 10；max_searches 默认 24 且必须 ≥ broad_queries + len(directions)*queries_per_direction（计划超预算直接 preflight 失败，让编排者改计划）；max_fetches 0..30 默认 8；fulltext_max_chars 默认 40000；max_attempts ≥1 默认 2；step_timeout_seconds 默认 1200；timeout_seconds 默认 5400。
- `plan_file` 可选：给了就必须是仓库相对路径（用 explore-repo 的 safe_rel 校验）且文件存在。
- preflight 还检查：git 可用、`acpx`/`codex`/`python3` 在 PATH、**环境变量 `METASO_API_KEY` 非空**（缺失即 fatal）、写 baseline.json 与 contract.snapshot.json（照抄 explore-repo）。

## 执行阶段（driver.py 子命令）

driver 子命令：`preflight | broad-search | deep-dive | synthesize | verify | assert-passed | finalize | selftest`。workflow.yml 全部为固定 `shell` 步骤调 driver，无任何插值（照抄 explore-repo 写法，requires speckit_version ">=1.2.0"）。

**codex 调用**照抄 explore-repo 的 run_explore：`acpx --cwd REPO --approve-all --model gpt-6-luna codex exec -f <prompt 绝对路径>`，stdout/stderr 落 logs/<call-id>.log，超时（step_timeout_seconds）与退出码非 0 均 fatal。每次调用的 prompt 由 driver 按固定模板生成并写进 `prompts/`。prompt 全部中文，明确：只读给定文件、只写指定产物文件、禁止访问网络、引用格式 `[S<数字>]`。

**搜索执行（可信脚本，不经 AI）**：python3 标准库 urllib POST `https://metaso.cn/api/v1/search`，Bearer `$METASO_API_KEY`，body `{"q","scope","includeSummary":true,"size","includeRawContent":false,"conciseSnippet":true}`，超时 30s，失败重试 1 次，仍失败记 `{"ok":false}` 不计预算；原始响应落 `raw/<qid>.json`。结果进 `sources.json`：按 URL 归一化（去 fragment、去尾斜杠）去重，sid 全局递增 S1..Sk；每条 `{sid,url,title,snippet,summary,date,scope,query_ids[],direction(null|"D1"..)}`；`searches[]` 记每次 `{qid,q,scope,direction,count,ok,at}`；`budget{used,max}`。**预算在发起搜索前检查，超限的查询丢弃并记录，不报错**。broad-search 结束若成功搜索为 0 条 → fatal。

**全文抓取（可信脚本）**：codex 产出可含 fetch 提案 `{"sids":["S3",...]}`（落 fetch-requests/ 留档）；driver 对其中 sid ∈ sources.json 且尚未抓取的项，POST `https://metaso.cn/api/v1/reader` body `{"url"}`、Accept: text/plain，响应纯文本截断 fulltext_max_chars 落 `fulltext/S<sid>.txt`；同样受 max_fetches 预算约束（超限丢弃记录）；单条失败记日志继续。

**阶段流程**：
1. `broad-search`：(a) codex 读契约+plan_file → 写 `queries/broad.json`（提案文件直接写在产物目录，driver 读后按 schema 校验并改写为 canonical）；(b) driver 执行搜索；(c) codex 读结果摘要（title/link/snippet/summary 清单）→ 写 `notes/broad.md`（≥500 字节，含 [S#] 引用）+ fetch 提案；(d) driver 抓全文。
2. `deep-dive`：逐方向（顺序，不并发）：(a) codex 读契约+该方向 questions+broad notes+已有 sources 摘要 → 写 `queries/<Di>.json`；(b) driver 执行搜索（direction 记为该方向 id）；(c) codex 读新结果摘要+notes/broad.md+fulltext 索引 → 写 `findings/Di.md`（≥300 字节，逐条 questions 给回答，每条至少 1 个 [S#] 引用）+ fetch 提案；(d) driver 抓全文。
3. `synthesize`：codex 读契约+plan+notes+全部 findings+sources.json+fulltext 索引 → 写 `report.md`。**固定章节及顺序**（verify 逐字检查标题、顺序）：`# `（标题自由）→ `## 执行摘要` → 每个 `## <方向id>`（各方向一节，按契约顺序）→ `## 交叉对比与矛盾` → `## 证据缺口` → `## 结论`。全文 ≥1000 字节，引用 [S#]。
4. `verify`：**恒以 0 退出**，裁决写 verify.json `{verdict, failures, attempt}`，stdout 末行 `VERDICT=<pass|repairable|fatal>`（约定照抄 explore-repo）。检查项：
   - 文件齐全：report.md、notes/broad.md、每个方向的 findings/<Di>.md、sources.json；
   - report 章节标题与顺序（上述固定结构）、≥1000 字节；findings 各 ≥300 字节、notes ≥500 字节；
   - 闭环引用：report+notes+findings 里所有 `[S<数字>]` 都能在 sources.json 解析（悬空引用=repairable）；report 引用的不同 sid 数 ≥ 方向数；每个 findings/<Di>.md 至少 1 个引用；
   - sources.json 完整性：sid 唯一且连续、url 为 http(s)、searches[].qid 唯一、每条 source 的 query_ids ⊆ 已有 qid、budget.used == len(searches) 且 ≤ max_searches、fetch 记录 ≤ max_fetches（损坏=fatal）；
   - 写入边界：与 baseline 的 porcelain 差异必须落在 `{产物目录 + .specify/ + 契约 allowed_write_paths}` 内，越界=fatal（violates/porcelain_paths 照抄 explore-repo，含 NUL 解析与祖先折叠语义；白名单额外加 `.specify/` 根，因引擎运行态目录在本工作流中也属合法写入）。
5. `assert-passed` / `finalize`：照抄 explore-repo（finalize 写 summary.json：task_id、workflow_id "deep-research"、model、attempts、report 绝对路径、来源数、搜索使用数、finished_at + SUCCESS 文件）。

**修复分支**：workflow.yml 里 `if`（condition 照抄 explore-repo 的 `contains('VERDICT=repairable')`）→ `repair` → `verify-again` → `final-check`(assert-passed) → `finalize`。repair 是一次 codex 调用：输入 verify.json 的 failures 明细 + 现有 report/findings/notes 路径，**只许编辑这三个位置的文件**，禁止发起新搜索（driver 在 repair 阶段不提供任何搜索能力，修复只改文本）。repair 计入 attempts（上限 max_attempts），attempt 记进 verify.json。

**codex 输出的 JSON 提案校验失败**（queries/fetch 提案不合法）：同一次调用允许重提 1 次（driver 生成一份附错误说明的追加 prompt 再调一次），再失败即 fatal；这不算 repair attempt。

## selftest 子命令（离线自测，无网络、无 codex）

`driver.py selftest` 用内置 fixture 断言：契约校验各拒绝路径、查询 schema 校验、URL 归一化去重与 sid 分配、`[S#]` 引用抽取与悬空检测、报告章节顺序检查、预算记账、violates() 越界判定。全过 exit 0，任一失败 exit 1。实现里把可测函数与 subprocess/codex 调用解耦，便于自测。
