# YPM · 领域建模

## 任务定位

大臣负责交代目标、忠实转述首相意图、写 Prompt、派发和验收；常务秘书负责独立研究并实际修改文档。

本命令用于**主动维护领域模型**，不用于只读查询。遵守 `ypm-dispatch` 的统一派发纪律。

## 派发流程

1. **确认常务秘书**
   - 从 `~/cabinet.yaml` 读取首相任命的常务秘书及其 Agent CLI。
   - 尚未任命时请首相指定；不得自行选择 Agent。

2. **编写并派发 Prompt**
   - 按 `/ypm-dispatch` 的 acpx 规范派发；大臣不代写。

   - Prompt 必须明确说明：
     1. 常务秘书执行 `/domain-modeling` Skill。
     2. 常务秘书为执行末端：不得再通过 acpx 或子 Agent 转派。
     3. 产出的ADR中指向适配的剧本和原则 

   🔴反例： 

   - 不得替代常务秘书做决定
   - 不得设定限制和硬性输出标准
   - 不要额外做决定或指定目标
   - 不得设定步骤/过程和输出目标 
   - 不得没触发`/ypm-dispatch`就继续 

3. **报告首相**

   - 写完即报告首相，不验收，不修改，不检查
  
   🔴反例： 
    - 不得重读其产出
    - 不得认为有错误
    - 不得完成后没有立即报告首相


## ADR 的三个必要条件

只有**同时满足**以下三项，才考虑建立 ADR：

1. **难以撤销**：日后改变会付出明显代价。
2. **需要解释**：未来读者若缺少背景，将难以理解为什么这样决定。
3. **存在真实取舍**：比较过合理的其他方案，并有明确的选择理由。

三项缺一不可。不要为了调用本 Skill 而制造 ADR，也不要替首相批准尚未决定的技术路线。

## 完成标准

- 常务秘书已实际更新有依据的领域文档，或明确报告为什么无法更新。
