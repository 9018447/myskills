# 解决合并冲突

## 触发条件

分支存在未解决的合并冲突，需要一条可靠的路径达到可构建状态。

## 工作流

1. 通过 git status 和冲突标记找出所有冲突文件。
2. 以最小、正确性优先的编辑解决每个冲突。
3. 安全时优先保留双方。否则选择能编译且保持公开行为稳定的版本。
4. 用包管理器工具重新生成 lockfile，不要手工编辑。
5. 运行编译、lint 和相关测试。
6. 暂存已解决的文件，并总结关键决策。

## 护栏

- 改动保持最小且可读。
- 任何文件里都不得残留冲突标记。
- 解决冲突期间避免大范围重构。
- 冲突解决期间不要 push 或打 tag。

## 输出

- 已解决的文件
- 值得注意的解决取舍
- 构建/测试结果
