# 验证与复审规则（jev 优先）

## 硬约束

代码复审、完成工作的确认、事实核对——这三类判断优先交给 jev 系列技能，而不是主 agent 自己逐一通读材料下结论。jev 是一个判定服务：把问题整理成类型化的判定请求（真/假、选项、分级），批量返回带置信度的结论，比自由文本式的自查更快也更一致。

- **代码复审** — 用 `jev-code-review`。把改动 diff、关联的测试证据和复审标准交给它，得到带证据的 review 结论。它产出的是审查线索，不是合并批准；测试仍然要真正跑。
- **完成工作确认** — 用 `jev`（批量判定）。把"这项是否完成、是否达标、下一步走哪条"整理成一批独立问题一次提交；同一状态下的多个问题合并成一次调用才有速度优势。
- **事实确认 / 陈述与原文比对** — 用 `jev-documents`。把原文段落和待核对的陈述交给它，保留它给出的引用出处和 no-match 结果；不要凭记忆断言"文档里写过 X"。

## 边界

- jev 的结论是判定辅助，不是授权或安全边界；要不要改代码、要不要发布，仍由主 agent 决定。
- 精确规则和算术用代码算，不问 jev。
- 判定前把相关上下文（diff、测试输出、原文段落）备齐再提交；上下文不足的判定结果不可信，补齐后重问。
