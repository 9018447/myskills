# 验证与复审规则（jev 判定优先）

## 硬约束

代码复审、完成工作的确认、事实核对——这三类判断优先交给 jev 判定服务，而不是主 agent 自己逐一通读材料下结论。

jev 的用法：把已知事实整理成一段 `state`（只放已经掌握的事实，不把原始文件整篇读进来），把要判定的问题整理成一批类型化问题一次提交，每种问题写清判定的含义：

- 真/假判断（noul）——"测试通过了吗""这个改动是否覆盖了所有调用方"。
- 选项判断（choice）——"下一步是修代码、合并，还是先补测试"，每个选项注明选中意味着什么。
- 分级判断（score）——"验证完整度打几分"，按从差到好列出等级描述。

服务对每个问题返回答案、置信度和分布；一批问题一次调用通常几秒内返回，比自由文本式的自查更快也更一致。

## 边界

- 置信度低或标记 escalate 的问题由主 agent 自己判，不要硬套 jev 的答案。
- jev 的结论是判定辅助，不是授权或安全边界；要不要改代码、要不要发布，仍由主 agent 决定。
- 精确规则和算术用代码算，不问 jev。
- 判定前把相关上下文（diff 摘要、测试结果、关键陈述）写进 state；上下文不足的判定结果不可信，补齐后重问。
