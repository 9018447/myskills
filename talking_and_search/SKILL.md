# talking_and_search — 提问 + 搜索的讨论循环

目的不是直接给出答案，而是通过一轮一轮的提问和搜索，把阻塞问题的主要矛盾找出来、解决掉。

## 循环步骤

1. **停下**：不要直接回答或动手。先用一两句话向用户复述你理解的当前问题和处境，确认没有理解偏。
2. **找主要矛盾**：判断当前把问题卡住的众多因素中，哪一个是"解决了它其余都松动"的那个。把它明确说给用户："现在的关键矛盾是 X，因为 Y。"
3. **提一个问题**：向用户提出**恰好一个**苏格拉底式问题——它应该帮用户（或你）检验对主要矛盾的假设，而不是一次问一串。等用户回答。
4. **搜索补充**：每当提出新问题、或收到用户的新回答后，用 metaso 搜索与当前矛盾相关的网页知识（命令见下文）。读完结果后判断：刚才的假设是否被证实、修正或推翻。
5. **进入下一轮**：带着搜索到的知识修正对主要矛盾的判断，回到第 3 步提下一个问题。

**完成判据**：主要矛盾被解决（用户认可的处理方式已明确），或用户说停止讨论。此时停止提问，向用户输出一段总结：主要矛盾是什么、每一轮讨论把判断如何修正、最终结论和下一步。之后如果用户要求，再回到正常工作模式。

**约束**：一轮只有一个问题。搜索是给"下一个问题"补弹药用的，不是拿来长篇汇报的——向用户转述搜索结果时只说影响判断的部分。

## metaso 搜索命令

从环境变量读密钥（`METASO_API_KEY`）。`q` 换成当前矛盾的具体问题（中文即可），`size` 一般 10：

```bash
curl -s https://metaso.cn/api/v1/search \
  -H "Authorization: Bearer $METASO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"q": "<当前矛盾的问题>", "scope": "webpage", "includeSummary": true, "size": "10", "includeRawContent": false, "conciseSnippet": true}'
```

`scope` 可选：`webpage`（默认）、`news`、`wechat`、`arxiv`、`github`。响应里有摘要和带 URL 的结果条目；需要细节再按 URL 取原文。
